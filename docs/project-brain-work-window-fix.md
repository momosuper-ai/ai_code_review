# Project Brain 2.3.1 工作窗口与恢复认证修复

核查/修复日期：2026-10-27。本文区分现场证据、确定性复现、代码修复与真实生成验收；最终验证记录以根目录 `AGENT.md` 为准。

## 现场证据和根因范围

2.3.0试点在编译123/127时停止，97个复用已包含在123内。失败单元有4次语义请求和6次隐私请求，全部结算；前三次语义响应的固定诊断类别为 `invalid_json`，第四次之后进入输出隐私检查。当前构建163次调用均已结算，没有HTTP错误账、unknown或在途费用。现存元数据不支持把本轮直接归因于HTTP500或休眠。

已确定复现的工程缺陷是：上层扫描检查剩余时间仍够，后续完整认证使剩余时间跌到请求timeout以下；`run_model_call`在尚未准备、预留或发送新请求时，也抛出 `ModelTransportFailed/model_http_retry_window_exhausted`。这绕过了输入正常让出和输出正确终态的既有分类。两个真实调用链的假时钟测试在旧实现稳定失败，修复后通过。历史日志没有保存当时的精确拒绝阶段，不能将合成复现写成那次现场请求的逐指令回放。

同时，认证计数和纯合成profile确认：每次发现检查会重新认证恢复父；未变化父反复进行相同JSON/HMAC/历史解析，已命中记录还继续查后续父。这消耗与语义重试、输出扫描共用的480秒工作窗口。真实失败单元两次隐私请求之间约16秒没有本单元账内请求在途，但未分段profile，不能将全部间隙精确归给认证。没有找到可确定复现的JSON解析器错误，非法JSON仍按原协议拒绝，不做宽松解析或绕过结构校验。

## 修复行为

1. **工作准入与HTTP恢复分离。** 新增 `ModelWorkAdmissionDenied`，固定区分准备前、准备后/预留前和预留后；记录角色、原因、剩余/要求时间、paid-output状态及是否已预留，不记录正文、URL或供应商异常文本。准备完成后再检查窗口，减少已知不能发送时的无谓预留。
2. **按付费边界处理。** 未预留、未发送语义请求的输入工作可保留收据后正常让出；已付费输出仍须完成必要隐私检查，否则按输出窗口终态停止。格式重试不能通过让出重置次数。预留后拒绝继续保留未知费用保护，不伪造零费用结算或自动重发。真正关闭HTTP错误后的重试窗口不足仍属于HTTP恢复终态。
3. **完整内容校验下复用认证解析。** 每个原认证边界继续读取完整key/index/state/seal、收据名/内容，以及历史清单和全部引用快照。只有新鲜读取的完整内容与本次真正认证过的材料一致，才能复用RAM中的解析结果；不用mtime、文件大小、TTL或无界全局缓存。双读并发检查保留，无法完整枚举依赖时回退原认证。
4. **防止缓存配错认证内容。** 缓存还绑定真正认证的材料、收据清单和历史语义，拒绝“A→B→A”变化使缓存A配上解析B的情况。相同大小、恢复时间戳、合法旧索引回滚、晚发现、封存变化、缺失或符号链接均有回归。
5. **只查尚未命中的记录。** 第一父已覆盖的记录不再送给后续父；全命中即结束查找。所有父仍由原发现检查认证。跨父或跨批次发生当前revision变化时，丢弃整组旧命中重新扫描，不能给旧命中套新revision。

任务600秒soft/660秒hard时限、480秒工作窗口、模型/隐私配置、调用次数上限与费用保护均未扩大。没有新增配置项或数据库迁移。合法输出确实无法在剩余窗口完成隐私校验时，仍会安全停止；本修复不承诺无限重试或任意模型输出都能完成。
