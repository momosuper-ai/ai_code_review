# Project Brain 认证检查点恢复

2.2.0 将完整运行配方与阶段内容兼容性分开。传输修复不再天然意味着重新生成全部知识；固定 SHA、完整隐私校验和可验证来源仍是前提。

## 恢复行为

| 场景 | 行为 |
|---|---|
| 同配方、无不完整调用 | 原 retry 保留成功单元，只重试失败单元 |
| 配方变化或旧构建有 unknown | 新建恢复执行记录，认证继承成功检查点；旧账保持原归属 |
| HTTP 后端、退避变化 | 完整审计配方改变；内容指纹兼容时允许继承 |
| 模型、提示词、输入、Schema、隐私规则变化 | 失效受影响阶段及下游，不凭名称或事实 ID 命中 |
| 未扫描响应已丢失 | 重做该编译单元，不保存或补用未扫描响应 |
| GitLab 发布失败 | 只重试发布，不重复生成知识 |

恢复记录的 `mode=full` 表示最终必须形成完整版本，不表示每个单元重新调用模型。恢复始终 `historical=true`：固定父 SHA，不恢复暂停分支、不切当前版本、不自动写回 GitLab。

## 阶段兼容性

`recipes.py` 提供 scan、extract、privacy、compile、summary、render 六阶段指纹，按依赖向下传播。完整配方仍包括全部核心实现、生成器、模型配置、HTTP 传输及运行时；单独提高 Token 上限不改变配方，也不清零账目。

内容指纹保守绑定解析器、SDK、Pydantic、上下文限制、模型及扩展参数、提示词、Schema、分包和隐私实现。SDK 内容处理和 Worker 业务函数以 AST 绑定，原 `_guard_base` 与恢复包装分离，历史 `_guard` 仅规范化名称；未知业务变化仍会失效。组件相等只是必要条件，来源、完整输入、结果及隐私状态另行认证。

## 私有认证与导入

迁移 `009_brain_recovery` 只新增 `brain_recoveries`，保存父子身份、封闭计划、输入/结果摘要和逐单元 imports；不保存源码、模型正文、密钥或映射。父子外键 RESTRICT，禁止自继承，有恢复历史时拒绝降级删除该表。

登记由项目行锁串行化。同父同配方的活动请求复用一个子构建。只接受 failed、公开 Schema 2、无活动租约或在途预留的父构建；安全隔离和封存冲突拒绝继承。父 unknown 不复制为当前调用或成功证据。

在任何模型调用前，Worker 认证并冻结父 key/index、来源 MAC、seal、历史和完整收据库存，同时绑定数据库单元与调用指纹。父 key、收据和 origins 不复制进子账。每次打开及最终封存复核；父检查点、调用结算或隐私材料改变即阻断。祖先最多八层，成环或超限失败，不截断来源。

隐私收据按完整 text 与语义 field 精确匹配。当前规则、历史发现和 HMAC 在命中前后仍生效。不同密钥下的同值可以复用；已经包含不同占位符的文本不能凭形状归一化。继承仅发生在 guard 的 RAM 视图，不伪造当前收据或 SDK 调用；正常新扫描照常持久化。

新的 Worker 在接受父隐私写入前先持久化写意图并隔离所有后代，再进入私有索引更新；写成功才清除自己的意图。并发写各有 UUID，进程中断留下的意图会阻止继续恢复，不能自动当作空记录。这样即使晚到发现发生在子版本 ready 之后，也会撤销可用性；文件锁与数据库锁不反向嵌套。

编译包还要求父单元 completed、原调用成功或完整恢复、原输入/结果摘要匹配、当前固定输入相同、事实及证据有效、当前隐私投影不改变结果。项目、源码、单元类型、包序号和完整 payload 一致；False、0、0.0 不混同。不满足时重做该包，不删除结论制造命中。

汇总和组装读取完整的继承结果与新结果，重新执行完整性、证据、隐私、调用和不可变封存门禁。本版不直接继承旧 summary/assemble，也不继承未完成输出。

## 历史构建证明

旧构建没有组件指纹时默认拒绝，不能回填当前指纹。管理脚本 `scripts/brain_recovery_attest.py` 必须在实际旧镜像、原运行配置与 SDK 环境中执行：

```text
python /tmp/brain_recovery_attest.py \
  --build-id <父UUID> --expected-recipe <原完整配方哈希> \
  --recipes-module /tmp/brain-recovery/core/project_brain/recipes.py --workers-drained
```

脚本与组件计算模块从已审阅的新发布只读挂入旧镜像，模块挂载路径保留 `core/project_brain/recipes.py` 层次，不能使用客户上传代码。先验证旧 `lifecycle.recipe_hash()` 与 DB 完全一致，再签名阶段证明至 Worker 私有卷；不改旧 DB/账目/检查点，不启动恢复，不调用模型或 GitLab。原配置必须有可靠来源，不能只拿旧源码加新配置证明历史。缺旧镜像、配置或私有材料则拒绝。

旧 Worker 没有后代隔离回调，因此认证旧版本前必须实际停止并排空旧 Worker；`--workers-drained` 是管理者对此操作的显式声明，也进入签名证明，不是脚本代为检查容器的结论。缺少排空证据不执行历史继承。

2.1.0 与本实现的六阶段代码兼容性已在旧不可变镜像离线对照，但这不代表项目 480 的实际检查点已经认证或已经授权新的模型费用。

## 接口与费用

沿用共享 API Key、IP 与限流规则：

| 方法 | 后缀 | 用途 |
|---|---|---|
| GET | `/builds/{parent_id}/recovery-plan` | 只读候选阶段数，明确 `candidate_only` |
| POST | `/builds/{parent_id}/recovery` | 空请求体或 `{}`，登记恢复并返回 202 |
| GET | `/builds/{child_id}/usage` | 当前新调用用量，另列父历史账及复用数量 |

客户端不能覆盖 SHA、模型、配方、预算、项目地址或本机路径。Broker 失败仍保留已登记的同一子构建，等待调度；父被引用后不能原地 retry。

历史调用与 unknown 保持原 UUID、归属和费用，不重复计为新调用。用量另列历史实结、占用及未知额；没有价格仍不虚构金额。manifest 记录父身份、认证清单/导入证明摘要、实际复用数和历史费用上界。当前新调用全部结算不表示历史费用已经明确。恢复不会自动扩大授权额度。

## 部署与验证范围

先停专用 Worker/Beat，保持 Brain/写回关闭，备份并迁移至 009，再用同版 API/Worker。新 Worker 不得抢先访问 008，也不得用新代码原地续旧付费检查点。父失败版本及私有历史是恢复依赖，不可人工删除。

本次只做离线合成与一次性 PostgreSQL schema 验证，不迁移运行库、不启动试点恢复、不消费真实模型额度。实际可复用数量须在私有认证后报告，不能把合成命中率当作实际节省比例或知识质量。
