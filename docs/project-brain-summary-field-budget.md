# Project Brain 2.3.3 概览字段预算与有界纠正

2.3.2 的真实验证已完成全部127个编译单元，但在模块汇总103/104处停止。失败单元的四次语义响应依次为概览过长、JSON格式错误、概览过长、概览过长。两次只读输入重放均通过；这次失败来自模型输出未满足概览契约，并非输入包无法合并。

4,000字节是默认概览输出预算，统计标题、正文、未知项及建议路径的规范JSON UTF-8大小；它不是模型的上下文容量。2.3.2 只有总预算提示和相同的纠正反馈，模型需要自行估算字节数。2.3.3 把这个要求落实为可单独检查的字段预算。

## 输出契约

默认配置下，首轮请求使用以下预算：

| 字段 | 首轮约束 |
|---|---|
| title | 最多40个Unicode字符 |
| S1.texts | 1～3条，每条最多115字符 |
| S1.unknowns | 最多1条、54字符 |
| 顶层unknowns | 最多1条、54字符 |
| document_path | null，或最多160字符的合法建议路径 |

预算先扣除完整JSON结构的固定开销，再按每个Unicode字符最坏六字节的JSON转义开销分配。满足字段约束的可编码结果不会超过原总字节预算。字符限制计算随原包配置变化，原4,000字节默认概览预算和32,000包边界没有上调。

相同字段定义同时进入系统提示和结构化输出Schema。工具调用兼容层仍移除供应商可能不支持的maxLength/maxItems，但保留字段说明；本地对已通过来源绑定校验的完整响应重新检查，不能把工具调用正常结束或供应商strict标志当作合格证明。

## 纠正与诊断

超出总字节或字段预算时，继续使用原有有界格式纠正次数。反馈只包含固定类别及数值：实际总字节、限制、各字段大小、条数和超限类别，不回传不可信正文。正文及未知项的字符预算逐次降为首轮的75%、50%，标题和合法路径空间保持；中间出现JSON格式错误或重新生成隐私安全投影时，已收紧的预算不丢失。

连续不合格仍会安全停止。新增固定错误码`summary_output_capacity`，在任务状态和API中与输入容量、上下文容量区分。没有增加重试次数、放宽模型预算、截断字符串、删除固定槽位或自动采用不合格输出。

概览只作有损综合。完整叶结论、证据和历史未知项仍由规范详情保存。隐私处理后的总字节校验、检查点封装校验和来源认证继续保留；不会为了缩短隐私占位符而破坏它们。

## 验证与边界

- 先复现4项缺口，再验证修复；242项定向测试覆盖JSON和工具调用、中文/控制字符/转义、模型忽略字段约束、重复未知项，以及超限后再遇JSON错误。
- 首个候选Linux断网完整回归2,237项通过、0跳过。最终镜像的测试结果及精确身份见根目录AGENT.md和被忽略的验证控制记录。
- 以真实固定输入和127个已完成叶结果，只在内存生成最坏转义长度的合成概览，5轮、108节点完成汇总树；最大包31,990，小于原32,000。原叶结果和全部历史未知项保持。这是规划及边界证明，不是模型质量评分。
- 最终候选与已重放候选的生产差异仅为类型标注；断网AST核对通过。运行库停止后没有伪称再次读取了实时数据。

本次没有部署、请求真实模型或重新构建业务知识，冻结50题尚未评分。原始不合格响应没有保存，因此没有声称逐字重放了真实模型输出；真实模型是否稳定遵守新契约仍需受控验证。

## 旧成果复用

旧127个编译及103个模块汇总检查点原样保留。这次修改触及共享编译器及其预算模块，按现有六组件认证，scan/extract一致，privacy/compile/summary/render不一致，兼容编译导入数为0；当前协议本来就不跨构建导入summary。

离线能够用旧叶结果验证规划，不代表生产可以绕过恢复认证直接使用它们。未修改、伪造或回填历史组件指纹，也没有把新配方注入旧付费单元。若要避免完整重算，需要另行实现并验证更细的编译/汇总内容兼容边界，然后重新认证真实检查点；不能只为获得复用数而放宽认证。
