# Project Brain 分层知识汇总

从 `project-brain/1.1.0` 开始，完整叶级知识先形成模块概览，再由完整模块集合形成唯一项目概览。项目文档不再直接拼接全部局部汇总。

```text
固定 SHA 的事实 / 关系 / 证据
    → 全部叶级编译检查点
    → 每模块的概览分片 → 必要的递归归并 → 唯一模块概览
    → 全部模块概览 → 必要的递归归并 → 唯一项目概览
    → 全部来源和完整性校验 → 不可变 JSON / Markdown / ZIP
```

## 完整详情与概览

卡片 `claims` 保存概览；新增 `detail_claims` 保留完整叶级解释和中间归并解释。`unknowns` 显示最终概览限制及源码覆盖缺口；`detail_unknowns` 保留完整继承限制。Markdown 在概览和导航后提供可展开的完整详情，JSON 与完整 ZIP 同时包含这些字段。旧卡片缺少新字段时按空列表读取。

概览是语义归纳，不是无损文本压缩。全部详细内容仍可追溯，但不能保证仅阅读概览就得到每一条细节。已声明却没有可编译事实的模块单独列出覆盖缺口，不伪造有证据的概览。

## 可恢复的汇总树

`summary.py` 提供确定性的分包、依赖重建、归并与最终覆盖验证。任务分为 `module_summary` 和 `project_summary`，仍使用现有 Brain 队列、租约、任务重试、预算与分模型记账；无需新增数据库迁移。

每个任务记录完整子检查点哈希、模块与叶级集合、结论/未知项的半开范围分片，以及规范输入摘要。模型调用之前，Worker 根据已完成的子结果重建输入，核对全部元数据；不能只信持久化 payload。模型费用计数与规范输入分开，计数不能影响输入哈希，未知费用仍继续占用额度。

单包默认最多 24 个完整子分片，使用现有 `PROJECT_BRAIN_PACKET_MAX_TOKENS` 的保守 UTF-8 容量上限；这不是供应商实际 Token。超过容量时只在完整结论或未知项之间分片，不切字符串；单条内容超过硬上限则明确失败。归并最多 8 层；完整概述后仍无法归并，或达到深度上限时停止，不能无限调用或发布局部项目概览。常量和实现文件均纳入生成配方。

模块任务可以并行执行；从 `1.1.3` 起，当前全局前沿完成后，独立 `planning` 单元规划下一前沿。项目汇总必须等所有有效模块概览就绪。失败子任务、遗漏模块、未知任务身份、输入变更或不完整根节点均阻止组装。乱序完成不会改变树、分包或文档顺序。重试保留成功检查点和累计费用。

编译和综合完成事务只保存已校验结果、检查轻量前沿状态并登记规划单元。规划读取一致数据库快照后关闭事务，在数据库锁外重建完整来源与计算容量；提交新任务时再次核对依赖签名、配方、租约和当前请求。下一层规划失败只使规划单元失败，不回滚已经合规的付费输出；同配方重试该单元不重新生成子结果。规划沿用 600 秒软超时，无模型调用，也无需新迁移。

## 综合协议与证据

每包只有一个由服务分配的 `S1` 槽位。模型解释整个当前子集合，可以比较职责和边界；它不能选择或生成事实、关系、证据或检查点 ID。从 `1.1.3` 起按输入层次使用两种关系视图：

| 输入层 | 协议与关系视图 | 模型实际读取 |
|---|---|---|
| 模块首层，`purpose=module, level=0` | `/2 symbol_graph` | 完整符号关系、候选目标和真实解析状态，按表编码无损传输 |
| 模块后续层、项目所有层 | `/3 resolution_counts` | 完整子概览及其概览未知项；按关系类型、解析状态、知识类型统计的精确数量 |

`/3` 明确是有损综合视图，不传逐条端点、目标名称或假定的模块归属。它保留当前规范输入去重关系总数及扫描前全部完整关系记录的 SHA256 摘要；摘要仅证明输入身份，不能证明业务语义。统计不能还原调用路径、证明具体模块依赖或冒充完整调用图。具体关系问题需读取保留的详细卡片与服务侧完整图。项目第零层已经消费模块概览，因此也使用统计视图。

完整规范输入仍保留逐条关系，仍全部执行隐私扫描；仅模型传输选择上述视图。没有删减事实、候选状态、来源或详情，也没有通过统计视图免扫原始输入。完整子文本和概览未知项不截断，超限仍按完整字符串分片或明确失败。

完整规范输入仍包含全部引用和来源，先执行完整隐私扫描。模型传输包含完整的当前子概览文本、概览限制和对应层的关系视图，通过局部子检查点身份及哈希描述来源；不重复传输所有叶级 SourceRef 元数据。服务将完整来源范围绑定到输出，并在正式产物保留引用。继承的详细未知项在服务端完整扫描和保留，上层同时获得概览限制、覆盖缺口和详情保留数量。局部传输身份或哈希不能证明结论得到业务语义支持。

综合 `source_scope.kind=summary_synthesis` 记录 `child_ids`、`module_ids`、完整 `source_ref_ids` 和服务绑定的 `relationship_view`。旧卡片缺少视图时保持 `null`，不推定其读取范围。新任务逐阶段严格核对视图，模型不能自行选择；JSON/API、Markdown 和独立审计均显示该边界。摘要绑定的是服务规范输入。文本始终是 `AI_INFERRED`，语义支持状态仍为 `unreviewed`。Markdown 明示这是解释输入范围。候选/未解析关系不会成为架构确定边界，综合文本不能被自动用作 Flow 的路径专属解释。

输入、输出、必要 reasoning、格式重试和最终卡片的隐私校验均保留；不保存原响应、不反脱敏、不删除非法结论后发布。`auto` 模式也执行固定槽位的应用侧校验；`strict_tool/source_bound` 沿用固定输出函数传输。

从 `project-brain/1.1.1` 起，身份校验区分原规范包与经过扫描的临时副本。HMAC 指纹可能同时匹配凭证值和文件路径的一部分；临时 `SourceRef.path` 允许变成过滤器对原路径的精确脱敏结果。原路径不会恢复到临时副本，也不会进入综合模型传输；规范证据、提交、blob、行范围、ID 和输入摘要仍保持原值。路径被任意替换、字段增加或其余来源身份改变时仍在语义请求之前拒绝。完整扫描和最终产物门禁保持不变；这不表示隐私分类结果已经通过独立准确率验收。

从 `project-brain/1.1.2` 起，事实和输入扫描仍以 8 次调用续跑；已经取得语义响应时，完整输出及格式重试必要 reasoning 使用独立的 `PROJECT_BRAIN_PRIVACY_OUTPUT_MAX_CALLS_PER_UNIT`，默认 64 次，范围 1～128。每次投递的 480 秒工作窗口、60 秒单调用限时、完整字段容量及全项目 Token 预算不变。次数上限只是停止条件，完成所需扫描后立即结束。输出扫描仍超出次数、时间或单字段容量时明确失败，不接受部分扫描、不保存未扫描响应、不丢弃后重新生成。新配置纳入配方；API 错误中的固定 `failure_code` 和数值日志用于区分容量问题。一次合规的长输出可能需要超过 8 个完整扫描包，不能从局部输入包的 8 次续跑上限推导其输出容量。

## 验证与上线

从 `1.1.4` 起，综合结果 envelope 只保存已扫描 `Compilation` 和不可变的子检查点/模块/叶级身份及摘要，不再重复保存派生的 `all_unknowns` 文本。重建时先严格认证完整 envelope，再从规范输入的完整继承未知项与当前 `Compilation.unknowns` 派生内存集合；后续输入仍完整扫描，卡片详情仍完整保留，最终 HMAC 再应用全部发现。Worker 不对已认证 envelope 整体再次脱敏，避免改坏机器摘要，或把晚发现的隐私规则造成的文本变化误判为检查点损坏。不能通过宽松比较、忽略额外字段或删除未知项实现兼容。

过去已完成检查点与配方保持不变。这个变更只消除结果里的重复正文副本；后续规范输入依旧按既有规则承载完整来源及历史限制，不是免扫或仅引用上下文的新协议。

验收分别验证模块覆盖、完整详情/限制保留、引用及 blob/行范围、候选状态、确定性调度、失败恢复、不可变哈希和分模型账目。独立质量审计同时检查概览和详情引用；引用有效率不能替代业务问题正确率。真实生成完成后仍须用固定源码的独立问题集评估职责解释、导航和业务答案。

更新改变生成配方，必须创建新构建；不能以新逻辑续跑旧失败构建的检查点或清零其账目。真实模型验证须有新的明确额度，GitLab 写回仍按当前授权保持关闭。单次首建不代表增量或发布验收通过。成本优化后续以这些质量约束为前提。
