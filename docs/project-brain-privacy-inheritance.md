# 已有隐私发现的继承

状态：`project-brain/2.0.1`已接入并部署到本机隔离API，Brain禁用、Worker/Beat停止；最终镜像1,524项单元及隔离PostgreSQL31项通过。本轮修复未重试da043b84或追加真实调用。

真实2.0.0构建说明：即使完整重扫，检测链也可能不再识别过去已认证的值。因此“模型本轮没有发现”不能撤销既有敏感标记。继承必须先于输入/输出扫描和缓存命中，覆盖同值路径、名称、说明及最终产物。

## 继承的证据与存储

- Worker按数据库GitLab项目归属选择已有私有HMAC材料，不能从API参数接收路径或URL，也不能混入其他项目。
- v2/v3旧账本先验证完整MAC及来源绑定；v1只保留明确的未知历史来源，不伪造其首次发现。缺失/损坏的应有材料报错，不能把它当成空发现。
- 旧key和不可逆索引以不可变快照保存在Worker私有`source-history/`，登记源build、SHA、格式和认证摘要；不保存原值、源码、上下文、邮箱或可逆映射。
- 对当前完整记录逐字HMAC匹配旧发现。值仅在当前记录的内存中取得，再以新构建key生成HMAC；不在模型或文档中恢复旧值，不把所有旧key搬进公开产物。
- 新指纹保留`inherited_hmac_match`来源：父快照身份/摘要、当前完整输入与字段的keyed摘要、封闭角色及位置计数。没有SDK调用，不创建或回填BrainModelCall。
- 规则引擎发现同样持久化为`deterministic_rule`，区别于真实模型发现，防止只在一个内存过滤器中有效、下一单元又忘记。

## 私有格式与运行门禁

私有指纹格式v3在finding中增加独立policy来源集合，保留原模型call/候选位置和legacy_unknown。每条policy记录有新构建key的MAC；不能冒充模型分类、确定业务事实或原始首次发现。v1/v2仍能按原契约读取，旧封存摘要不能被重写。

`CompilationGuard.clean`先应用继承与规则发现，再检查收据/构造模型输入；缓存与重启仍须重放完整HMAC。来源身份继续由SourceCatalog认证，不因脱敏改ID或删除条目。模型输出及必要reasoning也执行同一继承检查。最终封存与审计包括policy来源，仍保留完整四文件私有审计。

历史快照在首次extract固定，后续单元核对同一清单与MAC，不从变化的分支源码恢复。新增历史发现不静默修改已封存产物；本方案保证构建基线中已有发现不会被遗忘，不宣称跨版本全局即时撤回。

新Worker在首次建立key的同一锁内持久化认证空index；已有key却缺index或index被换成符号链接时停止，不重新建立空历史。旧2.0.0开放账本无法区分“从未写过空index”与“有发现的index丢失”，因此同样保守拒绝缺index，需离线核实，不能用兼容开关自动签空。更早版本完全没有可用私有材料时单独记录`privacy_history_legacy_unavailable`，不伪称完整继承。

已存在的audit目录不能回退到work；Schema2已就绪版本必须使用audit。导入时读取并认证完整key/index/state/seal，核对封存revision；冻结快照保留这四件套及其哈希，后续加载重复认证。缺件、合法但与封存不一致的旧index均拒绝。

`source-history/<project>/builds/`和`snapshots/`独立于临时work、公开产物及最近10版保留策略，仅Worker可读；与source-identities/source-seals/source-audits一起备份，当前不自动轮换或删除。父快照最多256份、指纹索引合计128MiB，超过时明确失败，不截断继承集合。独立审计新增可选`--privacy-history-base`，使用身份key标准位置时可自动定位；2.0.1正式清单的`privacy_history_digest`与私有基线、父来源、policy MAC必须一致，缺材料拒绝认证。

该改动纳入配方，无新环境变量或数据库迁移，不能继续2.0.0检查点；隔离失败或配方改变的retry接口返回409。继承与规则本身不产生模型Token，但完整扫描和语义生成仍按原预算记账，不能据此承诺项目总成本下降。

## 验收

1. 合成模型对旧凭证始终返回空items，已认证历史仍在任何SDK发送前隐藏该值；源码SHA/身份不变。
2. 凭证仅在路径、符号或说明中再次出现，同样继承；没有当前匹配的值不伪造新的分类因果。
3. 其他项目/伪造父材料、损坏MAC、缺失快照、重复记录、字段未知及位置错误全部拒绝。
4. 跨单元、收据命中、重启、预算等待及晚发现，全部出口无旧值，规则发现不因局部上下文消失。
5. 继承与规则不增加模型调用或费用；原真实用量与旧未知预留不变，四文件审计能验证新来源。
6. 原SHA零模型回放必须先证明4处路径/81条来源均被新构建自身指纹隐藏，再申请新的单次真实生成。
