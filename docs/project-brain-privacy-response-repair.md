# 隐私扫描响应纠正（2.3.4）

2.3.3 的一次真实执行在隐私扫描 152/165 时失败。数据库保存的固定错误与原 `compiler.py:868` 对应：返回的 `value` 为空，或不是本次实际发送文本的子串。该执行全部 857 次调用均已结算，没有 HTTP 错误或未知调用。原始响应未保留，不能进一步断言具体值、提示词误解或模型能力问题。

原逻辑严格拒绝了错误结果，但由任务层重试整个单元，未给模型任何固定纠错信息。2.3.4 保留原严格校验，在扫描包内最多进行两次纠正。仅反馈固定错误类别，重新发送当前完整安全投影；不回放错误响应，不接受部分结果，也不以失败代替空发现。JSON 字符串必须解码后逐字对应同一输入文本，不做模糊匹配、还原、拼接或截断。

每次发送仍独立预留 UUID 并结算。已有上下文、字段、输出、调用数量、时间和总费用上限不变。预算忙或时间不足不能通过让出任务来重置纠正次数；分包父节点也不能重新开启已耗尽的子节点。持续失败使用固定 `privacy_response_invalid` 类别终止单元，API 不再只能显示笼统的 `stage_failed`。有效检查点及所有费用继续保留。

合成测试覆盖空值、错误引用、非法 JSON/字段、有效和无效发现混合、拒绝响应、转义和 Unicode、发送前并发脱敏、预算/时间不足、分包重试上限，以及真实任务和计费接口。Windows 定向 163 项通过；最终候选 Linux 断网单测 2260/2260 通过，未跳过。首次完整测试的旧诊断类别不匹配已修正，诊断工具原单次模型探测预算没有增加。

这些结果证明工程行为，不证明真实模型一定能在纠正后返回合法结果，也不是业务质量验收。内容协议和完整配方已改变，不能将新代码注入旧付费单元；真实部署、生成、正式产物核验和固定 50 题评估需分别记录。
