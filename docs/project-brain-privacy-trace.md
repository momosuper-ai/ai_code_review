# Project Brain 隐私发现与源码身份冲突

`project-brain/1.1.5` 在不保存敏感原文的前提下记录发现的候选来源，并将源码路径冲突检查提前。它同时包含 `1.1.4` 的综合检查点修复。没有新增环境变量、数据库表或迁移；实现和格式进入生成配方，必须使用新构建，不能以新代码续跑旧配方或清零旧账。

## 要解决的问题

全局按值脱敏会遮盖该值出现的所有位置。某个字符串既作普通名称、又确为凭证时，路径也可能被遮盖；恢复原路径会违背隐私保护，替换规范路径又会破坏真实源码引用。因此冲突必须停止构建，不能按目录、标识符形状或公开名称一律豁免。

旧流程主要在最终组装才发现路径冲突，可能已花费大量模型用量。旧指纹只保存类型和长度，也不能定位哪个调用的哪些输入字段包含该值。本次改动使后续发现更容易追查，并减少已知冲突之后的工作；它不能自动判定旧发现是否误报。

## 不含原文的来源账本

Worker 私有工作卷中的 `privacy/fingerprints.json` 使用 `version=2`。同一个文件保存指纹、候选定位、调用绑定和整个 envelope 的 keyed MAC，持有同一索引锁后一次原子替换。文件和目录的权限沿用私有工作卷要求；账本不进入正式产物卷、仓库文件、API 或 ZIP。

每条新发现可关联以下机器信息：

- 调用 UUID，构建 UUID、单元 ID 和封闭阶段；构建记录进一步绑定固定 SHA 和配方。
- 当前扫描输入、实际发送记录、字段语义的 keyed HMAC，以及输入范围中的记录序号。
- 封闭字段类别、字符长度、首个匹配偏移、重叠出现次数、敏感类型和长度。
- 是否位于已收到语义响应之后的扫描窗口。

本地 HMAC 密钥只保存在 Worker 私有 `key` 文件中，用于重放和认证，不随知识导出。账本不会保存原值、原始字段名、源码路径、源码片段、模型响应、模型/GitLab 密钥配置、可逆脱敏映射或模型分类理由。输入和候选数量、文件字节数均有硬上限；超限拒绝整次写入，不能截掉部分来源后接受扫描收据。

候选定位只基于**本次实际发给扫描模型的脱敏后记录**。同值在多个记录中出现时保留全部候选记录，但这不证明模型依据哪个字段作出判断，也不证明分类正确。语义输出没有保存原文时，来源记录不能重建已丢弃的原响应。

旧 flat v1 索引仍可读取，其来源明确为 `legacy_unknown`，不伪造历史调用或回填当前单元。新格式的来源删改需通过 keyed 校验；兼容旧格式不等于具备完整文件反回滚能力。调用 UUID 也不能重新绑定到不同输入、上下文或发现集合。

Worker 写入顺序是：响应用量结算 → 严格验证 → 指纹与来源持久化 → 冲突检查 → 完成扫描收据。临时文件先 flush/fsync，再替换；支持的 Linux 文件系统上同步父目录以保证替换顺序。平台和底层存储仍须可靠实现这些操作，不能把原子替换等同所有硬件故障下的数据保证。已有索引或收据但密钥遗失时，拒绝生成新密钥冒充原账本。

`extract` 可以初建隐私账本；之后的隐私、编译和组装阶段要求既有账本，以 `create=False` 只读初始化。目录或密钥缺失、密钥长度损坏时使用固定 `privacy_checkpoint_missing` 终止，不创建新的空历史来配合 DB 中的旧完成状态。需要恢复原私有工作卷，或在获准后开始独立新构建；这不建立跨 DB/文件系统事务，也不能检测所有完整存储回滚或仅单个文件丢失。

## 提前停止与费用边界

每个 Worker 单元绑定完整源码身份集合：全部覆盖文件路径、模块目录、SourceRef 路径和 observation 路径，包括不可用或二进制文件的覆盖信息。

以下时点刷新并检查发现：

1. 绑定规范事实后、模型工作开始前。
2. 每次扫描入口及缓存、收据复用路径。
3. 新指纹与来源成功写入之后。
4. 首次语义请求、格式重试和预算等待后再次尝试预留之前。

冲突使用固定 `source_identity_privacy_conflict` 错误码与封闭分类计数，不输出路径、值或任意字段。它是终止错误，不是格式纠正或正常续跑信号；Worker 不通过三次自动模型重试掩盖冲突。已发生的调用照常结算，未知预留不释放，其他未完成单元按既有取消逻辑处理。

成功检查只在同一单元内复用。每次仍刷新共享指纹，缓存签名覆盖完整身份集合、完整指纹内容、已识别过滤器的规则、动态值、映射和实现状态；不是只比较条目数量。未知过滤器、未知状态或实现变化禁用缓存，失败不缓存。这样避免大项目在每个扫描包反复进行全量路径 HMAC，同时保留晚发现和同数量内容变化的检查。

发现文件、数据库租约和网络请求之间没有跨系统原子事务。因此已有并发在途请求仍可能完成或留下未知用量；提前门禁不承诺冲突后全局绝对零费用。最终完整路径、结构、引用及产物门禁继续保留。

## 查看与验证

私有审计收据完整复制允许的指纹 envelope，指纹数量只统计 `entries`，不能将版本和来源对象计入。审计脚本使用共享严格解码器，支持 v1/v2 并拒绝未知字段、非法类型、重复 JSON 字段。纯结构解码不证明 keyed MAC 真实性或分类正确；这些结论必须与 Worker 的认证和独立源码核对区分。

离线回归覆盖原子写失败、并发发现合并、密钥遗失、旧来源未知、候选记录遗漏/篡改、晚发现命中缓存、格式重试/预算等待前拦截、同数量指纹变化、规则变化、完整路径覆盖和账目保留。所有模型均为合成替代，不以此宣称真实项目的隐私精确率、召回率或业务知识质量。

上述实现与只读重放阶段没有新增真实模型请求。当时获准的两次合成对照已经执行完，485 Token 单独计入原轮额度；旧账与未知预留不变。不能通过删除旧指纹、放宽路径保护或无证据重建绕过。后续独立授权的构建结果见文末。

### 2026-10-16 本机部署验证

本机隔离栈已部署 `1.1.5`，API、Worker 和 Beat 使用相同镜像；迁移仍为 `007_brain_usage`。实际镜像内 Linux 全量回归 **1,310 项通过、8 项跳过**。API 与 Worker 的 23 份 Brain 源码哈希均与工作树一致；健康检查通过，项目保持暂停，执行中构建为零，GitLab 写回关闭。

仅使用原固定 SHA、既有事实检查点与旧隐私账本进行只读重放，新门禁在约 0.018 秒内拦住同样的 **4 个路径、81 条来源引用**。重放前后账本字节和原模型账目不变，模型请求、DB 写入和正式产物写入均为零。旧六条指纹的来源仍明确为未知，不由本次重放补造。

上述结果验证修复已部署且提前冲突门禁有效，没有证明真实分类一定正确或误报。项目仍无正式就绪产物，不能据此进行正式 50 题质量评分；后续应先核实冲突来源，再按明确授权范围验证新构建。

### 后续上下文对照与真实验证

继续只读区分持久标记与重放新增后确认：原事实与 132 个编译结果没有目标标记，重放分别新增 384、57 次；只有汇总 5739 的旧 `all_unknowns` 副本原本有 3 次。之前合计的 60 次不能当作 60 个原始发现。单元表没有完成时间，调用结算只提供时间代理；旧 v1 无来源记录，不能由时间邻近或并行请求证明最初分类来自哪个调用。

独立诊断 `scripts/brain_identity_context_diagnostic.py` 默认仅输出零联网计划，输入全部来自固定虚构模板，包含名称、职责解释、未知项、必要重试说明与路径。同样布局的正例仅多出一处明确的虚构凭证值。它不读试点文件，也不通过反脱敏或简单替换真实段落生成输入。

真实模式仅在新获授权后执行，必须同时提供环境门、冻结计划摘要及未使用的私有日志路径。计划绑定实际模型别名、网关/生成配方和诊断实现摘要，不输出网关或密钥。整体最多 2 次 SDK 发送、10,000 Token，每例一次，截断、格式错误、超时或非预期结果立即终止，不自动二分补发。日志以独占创建拒绝重复执行，发送前持久预留，缺响应保留未知额度；POSIX 使用文件及父目录同步，不能将此宣称为跨存储或全部硬件故障下的绝对保证。

来源校验比较全部候选位置、角色、HMAC、输入范围与同一个调用 UUID，MAC 必须可重开认证。正例应保存发现后触发预期身份冲突，不写包/记录完成收据；负例须没有指纹/来源，且全部收据完成。诊断没有将预期安全停止误作协议失败，也不把合法空 JSON 当成正例识别成功。

Linux 新诊断与相邻隐私回归 **151 项通过**。随后用户批准的真实两次请求也均通过：共 **622 Token（601 输入、21 输出）**，未知用量零，无 reasoning；负例零误报且无冲突，正例精确识别一个值、没有过宽圈定、完整绑定 8 个候选位置，重开后仍阻断。两次请求次数已经耗尽，不自动追加。

合成对照结束时，此前 485 Token 继续保留，独立 800 万轮已结算 3,252,836、未知预留 653,732，总占用 3,906,568，余额 4,093,432。该阶段旧构建账目、隐私账本和正式产物未改，GitLab 写回关闭，没有启动完整重建。以上结果支持有限样本下的模型区分能力与工程链正确性，仍不能证明旧发现误报或实际知识质量；后续真实项目验证须使用新构建及明确范围，不能续用旧配方或清除历史指纹。

### 授权新构建后的实际来源核验

用户随后批准一次使用剩余 4,093,432 Token 的 `1.1.5` 完整重建。构建约 419 秒后终止，完成全部 75 个事实隐私单元和 25/132 个编译单元；一个单元首次触发 `source_identity_privacy_conflict`，另 106 个随终止取消。本次结算 554,245 Token，未知和活动预留均为零；全轮占用 4,460,813，余额 3,539,187，旧 653,732 未知额度继续保留。单次授权已执行，余额不等于自动重试或新建授权。

本次来源账本经完整 MAC、调用归属、规范包及固定源码 blob 验证，两条候选的 record/field HMAC、长度、偏移和次数，以及完整实际发送记录组都严格重建匹配。独立 AST 确认标准库环境读取函数绑定且无源码遮蔽，目标均为第二参数默认值；其中一处的环境变量名与赋值目标属于凭证配置，另一处为连接元数据默认值。同值也出现在 4 个文件路径与 81 条来源引用中。

因此，本次分类有明确源码依据，不能按普通名称误报处理。仅凭调用名将默认值当成第一参数配置键会得出错误结论；静态凭证上下文也不能证明值有效或实际部署使用。该核验新增模型请求、DB 写入及账本改动均为零，不恢复或输出原值、路径、片段；它不回填旧 v1 最初分类原因。

现有策略下正确动作是终止，而不是删指纹、豁免路径或恢复受影响源码链接。此前曾建议先由维护者去除硬编码默认值再验证新 SHA；用户于10月19日明确要求必须支持原提交，这已成为后续产品要求，不再以业务源码修改为前置。当前采用 Worker 私有规范身份与对外安全知识投影设计，并同步覆盖证据、渲染链接、API/ZIP、增量及审计契约；仅改提示词不能解决这个冲突。全部待用源码摘录扫描也应提前到语义生成之前，以更早发现同类值，但不能取消后续输出扫描。完整设计和核心合成原型结果见 [敏感源码支持方案](project-brain-sensitive-source-design.md)；尚未集成生产协议，旧门禁保持。

本次没有正式 manifest 或就绪知识，50 题不评分，不能宣称可替代 AI_README。构建当时 GitLab 写回关闭、项目暂停、定时观察暂停；Windows 与容器窗口核验未发现电源事件、重启或 OOM，本次直接失败已绑定认证隐私发现。这些是该构建窗口的记录，不能充当后续日期的实时健康结论。
